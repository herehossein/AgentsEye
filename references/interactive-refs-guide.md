# Semantic Ref Locators Guide (`@e1`, `@e2`, ...)

`agentsEye` provides a deterministic semantic ref locator system (`@e1`, `@e2`, ...) designed for AI coding assistants and developers. While raw CSS selectors are brittle and break easily on modern component libraries, Tailwind CSS, or CSS Modules, semantic refs assign stable, 1-based sequential tokens to all actionable DOM elements.

---

## 1. Why Semantic Ref Locators?

Modern web applications present significant challenges for automated browser interaction:
- **Dynamic CSS Classes**: Utilities generated by Tailwind or CSS Modules change across builds or dynamic states.
- **Deep Nesting**: Fragile selector paths like `div > div:nth-child(3) > button` easily fail if markup shifts slightly.
- **Agent Context Budget**: Generating or guessing complex CSS selectors burns LLM context and frequently leads to interaction failures.

Semantic refs solve this by:
1. Scanning actionable elements during DOM inspection.
2. Allocating stable, 1-based numerical ref tokens (`@e1`, `@e2`, ..., `@eN`).
3. Associating each ref with its accessible name, tag, ARIA role, and bounding box.
4. Allowing agents to interact with zero selector guesswork via `--click @e1`, `--hover @e2`, or `--scroll @e3`.

---

## 2. 1-to-N Universal Indexing

Unlike tools that artificially truncate element discovery, `agentsEye` indexes **every** actionable element on the page into an internal registry:
- **Sequential Assignment**: Elements receive refs from `@e1` through `@eN` in document order, traversing open Shadow DOM roots and main document flow.
- **Actionable Criteria**: Elements are indexed if they match interactive tags (`button`, `a`, `input`, `select`, `textarea`, `summary`), interactive ARIA roles (`button`, `link`, `tab`, `menuitem`, `checkbox`, `radio`, `switch`), or have CSS `cursor: pointer`.
- **Physical Visibility**: Only rendered elements with non-zero dimensions (`width > 0 && height > 0`) and visible styles (`visibility !== 'hidden'`) receive refs.
- **Actionability**: Every allocated ref (e.g. `@e42`) remains immediately actionable via CLI interaction flags, even if it falls beyond the compact summary preview.

---

## 3. Subtree Scoping (`--interactive-scope`)

When inspecting complex pages with dozens of interactive elements, you can narrow ref allocation to a specific container or dialog using `--interactive-scope`:

```bash
# Scope ref allocation strictly inside a modal dialog
node agentsEye.mjs http://localhost:3000 --interactive-scope "#settings-modal" --temp

# Scope refs to a specific form or navigation drawer
node agentsEye.mjs http://localhost:3000 --interactive-scope "form#checkout-form" --temp
```

When scoped, elements outside the specified container are excluded from ref allocation, keeping ref counts minimal and focused on the active task.

---

## 4. CLI Interaction Commands

Semantic refs can be passed anywhere a CSS selector is accepted:

### Click via Ref
```bash
# Click an actionable button or tab by ref
node agentsEye.mjs http://localhost:3000 --click @e1 --temp
```

### Hover via Ref
```bash
# Hover over a navigation dropdown or tooltip trigger
node agentsEye.mjs http://localhost:3000 --hover @e2 --temp
```

### Element-Centric Scrolling
`agentsEye` supports two scrolling modes:
1. **Coordinate / Delta Scroll**: `--scroll X,Y` dispatches native CDP mouse wheel events (e.g. `--scroll 0,500`).
2. **Element-Centric Scroll**: `--scroll @eN` (or `--scroll "<css-selector>"`) brings the target element smoothly into view using in-page `scrollIntoView({ behavior: 'instant', block: 'center', inline: 'nearest' })`:

```bash
# Scroll element @e5 into viewport center
node agentsEye.mjs http://localhost:3000 --scroll @e5 --temp
```

### Chained Action Sequences
You can chain multiple ref and keyboard interactions sequentially (up to 50 actions):
```bash
node agentsEye.mjs http://localhost:3000 \
  --click @e1 \
  --key Tab \
  --hover @e3 \
  --scroll @e7 \
  --temp
```

## 5. Progressive Querying & Viewing

`agentsEye` follows a progressive disclosure pattern to balance token efficiency with complete inspection depth:

### 1. Default Budgeted Summary (`minimalSummary`)
Default CLI runs emit a compact summary with metadata and the top visible interactive elements:
```json
{
  "interactive": {
    "total": 34,
    "showing": 12,
    "items": [
      {
        "ref": "@e1",
        "tag": "button",
        "role": "button",
        "name": "Open Navigation",
        "rect": { "x": 16, "y": 12, "width": 40, "height": 40 },
        "smallTouchTarget": true
      },
      {
        "ref": "@e2",
        "tag": "a",
        "role": "link",
        "name": "Pricing",
        "rect": { "x": 80, "y": 16, "width": 64, "height": 32 }
      }
    ]
  }
}
```

### 2. Deep Slice (`--focus interactive`)
To inspect the complete catalog of all interactive elements across the page:
```bash
node agentsEye.mjs http://localhost:3000 --focus interactive --temp
```

### 3. Offline Querying (`show`)
Inspect specific elements or items offline without launching a browser:
```bash
# Show all indexed interactive items
node agentsEye.mjs show <run-id> interactive.items

# Query a specific item by index
node agentsEye.mjs show <run-id> interactive.items[15]
```

### 4. Compact Indented Text & Snapshot Deltas (`--compact`, `--delta`)
For ultra-dense token consumption during interactive loops:
```bash
# Format interactive elements as compact indented text (pruning non-interactive wrappers)
node agentsEye.mjs http://localhost:3000 --focus interactive --compact --temp

# Execute interaction and receive only the delta changes (or { kind: "unchanged" })
node agentsEye.mjs http://localhost:3000 --click @e1 --delta --temp
```

## 6. Interaction Safety Gates

Automated agents must not trigger destructive state changes or unintended page navigations. `agentsEye` enforces strict safety gates on all click actions:

### Inviolable Hard Blocks (Never Clicked)
The following controls are strictly blocked from automated clicks:
- **Navigation Links**: `<a href>` and elements with `role="link"` are never clicked to prevent unexpected navigation away from the inspection URL.
- **Form Submissions**: `<button type="submit">`, `<input type="submit">`, and default buttons inside `<form>` elements are blocked to prevent submitting forms.
- **Form Reset Controls**: Buttons with `type="reset"`.
- **File Upload Inputs**: `<input type="file">`.
- **Editable Controls**: Text fields, textareas, selects, and contenteditable elements.
- **Obscured Elements**: Elements failing `document.elementFromPoint(x, y)` hit-testing (e.g., covered by an overlay or backdrop).

### Destructive Keyword Blacklist
Interactive elements with labels matching destructive terms in English or Persian are skipped by default (`status: 'skipped'`):
- **English**: `delete`, `remove`, `pay`, `order`, `checkout`, `logout`, `cancel`, `terminate`, `destroy`, `purge`, `reset`, `submit`, `confirm`, `save`.
- **Persian**: `حذف`, `پرداخت`, `خرید`, `سفارش`, `خروج`, `لغو`, `انصراف`, `تایید`, `ارسال`, `ذخیره`.

### Safe Dev Server Override (`--allow-destructive`)
On controlled development servers, pass `--allow-destructive` to relax keyword filtering for labels like "Save" or "Submit". Even with this flag enabled, **hard structural blocks (navigation links and form submit buttons) remain permanently enforced**.

### Diagnosing Skipped Actions
When an interaction is skipped, `interactions.actions` records the exact reason:
```bash
node agentsEye.mjs show <run-id> interactions.actions
```
Common skip reasons:
- `Click blocked: navigation links (<a href> or role="link") cannot be clicked automatically`
- `Click blocked: form submission controls cannot be clicked automatically`
- `Click skipped: matches destructive keyword (pass --allow-destructive to permit)`
- `Element ref @eN not found or stale`
- `Target is covered or failed hit testing` (indicates an overlay or z-index issue)

## 7. Lifecycle Ephemerality & DOM Hygiene

Temporary DOM markers and in-memory structures used during ref inspection adhere to strict hygiene rules:
- **No Residual DOM Attributes**: The probe tags matched elements with `data-agentseye-ref="eN"` during interaction phases. Upon session completion, interaction end, or navigation, a cleanup routine strips all `data-agentseye-ref` attributes from the DOM.
- **Memory Cleanup**: The in-page registry stored on `globalThis.__agentsEyeRefsV1` is cleared when inspection finishes.
- **Telemetry Cleanup**: Passing `--ephemeral` unlinks all telemetry on exit. Passing `--temp` writes runs to OS temporary storage.
